# ARCHDS V8.4 — UML Reconstruction

## What changed
- Rebuilt requirement-to-UML extraction to use atomic functional user goals.
- NFR-only statements (availability, latency, scalability, global deployment, backups, logging, etc.) are excluded from use-case generation.
- Coordinated functional objects such as `view account balances and transaction statements` become separate use cases with the same action.
- `register and authenticate` remains one coherent use case.
- Domain classes are extracted only from explicit business entities; arbitrary requirement words cannot become classes.
- Class relationships are created from entities co-occurring in the same functional requirement, with semantic relationship labels where evidence exists.
- Same-row non-adjacent class relationships route through dedicated gutters so lines never pass through an intermediate class box.
- Cross-row class relationships use reserved gutters and orthogonal ports.
- Use-case actors are placed in dedicated vertical positions; each actor's use cases are stacked in dedicated rows to prevent actor/use-case overlap and crossing connectors.
- Sequence diagrams use the selected functional requirement, its requirement mapping, and candidate component evidence. No fixed banking/healthcare/e-commerce sequence is embedded.
- Sequence return messages are derived from the actual use-case name rather than a fixed template sentence.

## Validation
- `python -m py_compile ai-service/app/diagram.py` passed.
- `PYTHONPATH=. pytest -q` passed: 13 tests.
- Rendered SVG smoke checks for use-case, class, and sequence diagrams.
- Multi-actor smoke check confirmed separated actors and non-overlapping use-case rows.
- Banking, healthcare, and academic requirement examples produced different requirement-derived UML models.
