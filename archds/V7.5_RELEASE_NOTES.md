# ARCHDS V7.5 — Digital Twin + Closed-Loop Delivery Upgrade

## What changed

### 1. Digital Twin is now requirement- and intensity-sensitive
- 12 what-if scenarios are available instead of a single generic scenario.
- Scenarios include traffic surge, component failure, dependency outage, latency pressure, regional outage, security pressure, data growth, flash-event burst, disaster recovery, cost pressure, deployment rollback and observability degradation.
- Scenario relevance is computed from the submitted requirement profile.
- Stress intensity changes the simulation numerically; the result is no longer a static repeated diagram.
- Every run produces baseline metrics, post-stress metrics, deltas, affected requirements/components, a timeline and a proposed adaptive response.
- Digital Twin topology is rendered using a compact routed layout so nodes do not inherit the crowded original graph coordinates.

### 2. Closed-Loop Delivery Lab
- New project tab: **Delivery Lab**.
- Generates requirement-derived Terraform and Kubernetes starting artifacts.
- Runs deterministic local structural validation.
- Performs a feedback/repair pass if validation fails.
- Shows validation checks, iteration history and downloadable artifacts.
- Clearly labels the artifacts as development/research starting points; no cloud infrastructure is provisioned automatically.

### 3. PDF reliability
- PDF generation was simplified to ReportLab primitives instead of parsing large browser SVGs.
- Report now contains requirement intelligence, candidate competition, explainability/traceability, Digital Twin scenario catalogue and delivery-lab evidence.
- Frontend PDF request has a finite timeout so the UI cannot remain stuck on “Generating…” forever.

### 4. UML and evidence presentation
- Use-case connectors now use a single system boundary with routed actor lanes.
- Class relationships use outer routing gutters to avoid drawing through class cards.
- Entity extraction ignores connector/filler words such as `and`, `for`, `the`, `must`, etc., reducing malformed class names.
- Sequence diagram is explicitly labelled as requirement-derived.
- Evidence cards distinguish requirement evidence, optimization trade-offs and open review findings.

## Validation performed
- Python modules compile successfully.
- Digital Twin scenario catalogue returns 12 scenarios.
- Multiple stress intensities produce different simulation metrics.
- Delivery Lab generates Terraform/Kubernetes artifacts and passes structural validation.
- PDF generation returns a real `application/pdf` response in a local unit smoke test.

## Important limitation
The Delivery Lab performs lightweight structural validation only. It does not claim that generated infrastructure has been provisioned or production-tested.
