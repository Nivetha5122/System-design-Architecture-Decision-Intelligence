# ARCHDS V7.7 — Final Research-Grade UI/Diagram Hardening

## Purpose
This release hardens the architecture visualization and UML layers on top of V7.6 Digital Twin Evolution.

## Diagram hardening
- Architecture blueprint connectors use deterministic orthogonal routing with obstacle checks so edges avoid component cards.
- Blueprint defaults to a readable key-dependency view; all dependencies remain available through an explicit toggle.
- Use-case associations use actor trunks and orthogonal branches instead of a dense web of individual lines.
- Actor placement is derived from the use cases they actually own; automated system actions can be represented by a System actor.
- Domain class extraction filters generic/filler terms and action phrases so words such as `And`, `For`, `Must`, `Submit`, `Tracks`, and `Sends` do not become domain classes.
- Class relationships are routed through row gutters and do not pass through class cards.
- Sequence diagrams use the primary functional requirement and requirement-relevant runtime components rather than a fixed generic request chain.
- A dedicated Framework tab is exposed for the requirement-derived runtime request path and evidence.

## Explainability hardening
- Confidence values are normalized from either 0–1 or 0–100 before displaying percentages, preventing values such as 9100%.

## Environment limitation
The container used for packaging does not have Maven or Docker installed, and the provided frontend dependency tree does not contain a Vite executable. Therefore a complete React production build and Docker image build cannot truthfully be claimed as executed here. The project retains its Dockerfiles and is intended to be validated with `npm ci && npm run build` and `docker compose build` on the deployment machine.
