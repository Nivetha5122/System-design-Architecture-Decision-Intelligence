# ARCHDS V8.9.6 — UML Connectivity & Requirement Intelligence

## Fixes

- Reworked the Domain Class Diagram connector router. Associations are rendered orthogonally through whitespace gutters and outer channels, with class cards drawn over connectors so paths do not obscure attributes or operations.
- Domain entities are collected from the full submitted requirement corpus, not only action-object fragments. This improves connections between business entities mentioned in separate clauses of the same requirement.
- UML associations are generated only from co-occurrence evidence. The generator no longer invents inheritance, composition, or multiplicities when the requirement text does not justify them.
- PlantUML class source now uses association lines (`--`) rather than directional dependency arrows for domain associations.
- Architecture pattern retrieval now combines normalized tokens and phrase aliases, weighted lexical overlap, explicit architectural-driver matches, and optional semantic reranking. The default remains offline-friendly.
- Infrastructure and NFR concepts such as availability, latency, security, monitoring, cost and deployment are excluded from domain class candidates.

## Validation

- Python syntax compilation passed for changed modules.
- AI-service test suite: 15 tests passed.
- E-commerce smoke test generated six domain classes and eight requirement-grounded association links; SVG class diagram contains routed paths.

## Important interpretation note

Relationship inference is evidence-based but not a substitute for domain-owner confirmation. Multiplicity, inheritance and composition are only appropriate when the requirements or domain model explicitly support them. Architecture scores and retrieved patterns are recommendations, not guarantees of production performance.
