# ARCHDS V7.3 — UI / Explainability / UML / PDF Fixes

This release addresses the observed UI and artifact issues:

- PDF generation now returns a valid fallback PDF instead of an opaque HTTP 500 when an optional artifact is malformed; backend propagates AI report-service errors with detail.
- Project pages no longer auto-run analysis because of `?run=1`; Run again explicitly starts a job.
- Blueprint connector paths are routed orthogonally with separated lanes instead of crossing Bézier curves.
- Blueprint component requirement labels are shown as human-readable requirement descriptions rather than R1/R2/R3 IDs.
- Long component names are wrapped inside cards and the blueprint typography is stabilized for zoom/responsive layouts.
- Why this architecture, trade-offs, and risks are evidence-first and requirement-specific.
- Explainable AI shows each supplied requirement, its architectural driver, implementing components, and coverage.
- Use-case UML is grouped by actor to reduce line crossings.
- Class UML limits relationships and routes them through gutters for readability.
- Sequence UML is generated from the primary functional requirement and its actual candidate requirement mapping; it does not use a generic invoke/read/publish chain.
- Sequence labels describe the requested action and requirement text rather than displaying only R1/R2/R3.
- Explanation rationale explicitly references the supplied requirement descriptions and mapped components.
- Report evidence includes requirement-specific explanation evidence.
