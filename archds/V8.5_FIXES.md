# ARCHDS V8.5 — PDF, UML, UI and Decision Intelligence Fixes

## Fixed
- PDF download no longer remains stuck on `Generating…` because the missing frontend `reportToast` runtime function was restored.
- PDF downloads are forced through a browser Blob/Object URL flow and validated against the `%PDF-` signature before success is shown.
- PDF request timeout increased to 90 seconds to tolerate server-side report rendering and local fallback generation.
- PDF server endpoint retains `Content-Disposition: attachment` and a valid local fallback PDF when the AI renderer is unavailable.

## UML improvements
- Functional verbs are normalized across inflected forms such as `uploads`, `screens`, `ranks`, `detects`, `reviews`, `assesses`, `recommends`, etc.
- Recruitment/domain vocabulary now includes resume/CV, candidate, applicant, job/job role, skill, interview, assessment, recommendation, decision, bias and fairness concepts.
- System-originated actions are correctly assigned to the `System` actor instead of an incidental domain noun.
- Sparse candidate payloads can still produce a useful requirement-grounded sequence path by matching normalized requirement terms to candidate components/evidence.
- Existing requirement-to-component mappings remain the preferred source when available.
- Existing diagram routing/layout is preserved and the project test suite remains green.

## Alternatives / UI
- Candidate comparison now supports `Pareto first` sorting.
- Each alternative displays a strongest modeled dimension, a concise reason to consider it, and a concrete trade-off/risk.
- Existing requirement coverage, Pareto status, reviewer findings and component evidence remain visible.
- Added clear PDF toast states for generating, success and failure.

## Digital Twin
- Existing deterministic, requirement-grounded Digital Twin behavior is preserved.
- Scenario relevance, topology state, affected requirements, mitigation actions, evolution loop and decision gate remain intact.

## Validation
- Python AI-service tests: **13 passed**.
- Generated sample PDF verified as a valid PDF 1.4 file with attachment disposition.
- Recruitment-style UML smoke test verified actor, use-case, domain-class and sequence generation.
- Frontend production build could not be completed in the offline execution environment because npm dependency installation was not available; source changes were kept dependency-free.
