# V8.8 — Requirement-Exact UML Upgrade

## Fixed
- Use Case generation now extracts atomic actions from the actual submitted requirements, including recruitment verbs such as upload, screen, rank, shortlist, assess, match, recommend, detect, analyze and explain.
- Actor assignment is subject-first: Recruiter/Candidate/Administrator actions stay with the stated actor; system-driven actions are assigned to System rather than whichever actor happens to be mentioned in the requirement.
- Use Case names preserve the real action + business object (for example, `Screen Resumes Against Job Requirements`).
- Class generation is based on action objects from the submitted requirements, not a fixed domain template.
- Class operations are tied to the action that targets that class; unrelated operations are no longer copied across every class in a requirement sentence.
- Compound nouns such as Job Role, Application Status and Job Requirement are preserved instead of creating incorrect partial classes such as Job, Role or Statu.
- Sequence generation now includes an explicit System boundary, actor → system → domain-object interactions, completion/return messages, and requirement IDs for traceability.
- Sequence messages preserve submitted requirement order and are generated for the actual functional actions rather than one hardcoded workflow.
- Existing PlantUML and SVG generation remains supported.
