# ARCHDS V7.1 — Research UI & Architecture Artifacts Upgrade

## What changed

### 1. Runtime System Design Framework is now separate from the Component Diagram
The Framework view no longer reuses the component/layer graph. It now explains a runtime request path derived from the submitted requirements, for example:

`User / Client → [Global routing when justified] → [CDN when justified] → Load Balancer → WAF/Security Boundary → API Gateway → Identity & Access → Cache → Business Capabilities → Data & Persistence`

Only justified controls are inserted. A small low-traffic system does not automatically receive every infrastructure component.

The Framework view also shows the functional requirements and non-functional drivers that justify the runtime elements.

### 2. ARCHDS multi-agent research framework
A separate research-framework section shows:

Requirement Intelligence → Architecture Knowledge → Candidate Competition → Adversarial Debate → Refinement & Verification → Pareto Analysis → Architecture Judge → Explainability & Traceability → Human Decision Gate

The candidate competition is represented as independent alternatives; specialist reviewers challenge every candidate before refinement and Pareto analysis.

### 3. Requirement-derived UML
Each completed analysis now generates three separate UML artifacts from the user's actual functional requirements:

- Use Case: actors, system boundary, use cases and associations.
- Class: requirement-derived domain entities, attributes, operations and relationships.
- Sequence: participants and request interactions through the generated architecture.

No fixed hospital/e-commerce UML diagram is embedded.

### 4. Real PDF generation
`GET /api/projects/{projectId}/report.pdf` now returns an actual PDF generated server-side from the stored analysis result.

The report contains requirements, candidate competition, research framework, runtime system design framework, UML diagrams, selected architecture, risks/trade-offs and traceability.

### 5. Three-role RBAC
The visible role model is exactly:

- ADMIN
- ARCHITECT
- REVIEWER

New registrations default to REVIEWER. USER is no longer exposed as a workspace role.

### 6. No preset/demo requirement catalogs in the New Analysis screen
The production analysis form starts from the user's own system description and requirements instead of preloaded example systems.

### 7. Optimization terminology corrected
The implementation performs discrete non-dominated Pareto analysis. It no longer claims to execute NSGA-II.
