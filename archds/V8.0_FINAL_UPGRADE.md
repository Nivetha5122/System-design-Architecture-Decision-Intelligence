# ARCHDS V8.0 Final Architecture Intelligence Upgrade

## Product position
ARCHDS is a requirement-driven architecture decision and engineering workspace. It generates competing architecture candidates, evaluates them against the submitted requirements, exposes evidence, simulates counterfactual scenarios, and produces deployment-oriented artifacts.

## V8 upgrades
- Rebuilt UML semantic extraction so domain class names come from meaningful architecture capabilities and requirement concepts rather than arbitrary words from sentences.
- Use-case names are concise user goals derived from functional requirements; raw requirement sentences and requirement IDs are not used as use-case labels.
- Class relationships are created from explicit candidate architecture relationships or requirement co-occurrence, reducing invented links.
- Use-case, class and sequence connectors use deterministic orthogonal routing with dedicated whitespace lanes.
- Architecture blueprint dependency routing was simplified to avoid card intersections and dense spaghetti paths.
- Added **Ask ARCHDS**, an architecture-grounded advisor that answers questions using the stored requirements, selected candidate, reviewer findings, optimization evidence and architecture mappings. It uses deterministic reasoning when no external language model is configured and can enrich answers through the configured OpenAI-compatible provider when `LLM_API_KEY` is present.
- Removed requirement shortcut labels from the Architecture framework evidence surface.
- Rebuilt the PDF as a senior-architect-style Architecture Decision & Engineering Report with executive summary, requirement intelligence, candidate comparison, optimization evidence, traceability, architecture blueprint, UML package, Digital Twin scenario catalogue, delivery engineering notes, decision record and terminology.
- PDF generation returns an actual PDF response and was smoke-tested through the FastAPI endpoint.
- Confidence rendering now safely handles numeric and percent-string inputs.
- UI terminology was simplified: Architecture, Diagrams, Ask ARCHDS, Digital Twin, Delivery and Decision are presented as user-facing concepts rather than internal implementation labels.

## Important production boundary
Terraform and Kubernetes output remains deployment-oriented starting infrastructure. ARCHDS does not claim that generated infrastructure has been provisioned or that it has passed cloud-provider-specific security, networking, secret-management, image, capacity, compliance or operational approval. A responsible engineering team must validate those controls before production deployment.
